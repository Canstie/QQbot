# QQ Personal Bot

这是一个面向 NTQQ + OneBot v11 桥接方案的个人 QQ Bot 项目，可配合
LLOneBot 或 NapCat Framework 使用。桌面 QQ 客户端可以正常使用，同时 Bot
行为由群聊白名单/黑名单策略控制。

## 已包含功能

- 基于 NoneBot2 的入口和 OneBot v11 适配器。
- 使用 SQLite 保存群聊启用/禁用、黑名单、管理员、触发前缀、限流参数和审计记录。
- 群聊策略管道：群策略判断、触发条件判断、限流和默认回复；本人账号只允许前缀指令触发。
- 管理员命令：
  - `/d`（引用聊天记录，下载其中的全部图片并按内容查重）
  - `/dimg`（引用图片或表情，将其加入 AI 可发送的表情包库）
  - `/dov`（查看 MinIO 图库的图片总数、大小和今日新增）
  - `/rm <SHA-256>`（按完整内容哈希删除图库中的唯一图片）
  - `/bot on [group_id]`
  - `/bot off [group_id]`
  - `/bot aion`（开启 AI 总开关，使用独立的 AI 启用群名单；不改群名单）
  - `/bot aioff`（关闭 AI 总开关；不清空 AI 群名单）
  - `/bot aion <group_id>`（将指定群加入 AI 启用名单）
  - `/bot aioff <group_id>`（从 AI 启用名单移除指定群）
  - `/bot aioff all`（兼容旧命令，等同于 `/bot aioff`）
  - `/bot ai rs`（清空全部 AI 短期上下文）
  - `/bot aim list|<模型名>`（查看消息链路供应商模型列表，或切换消息模型）
  - `/bot aik list|<序号>`（查看知识库，并按列表序号切换）
  - `/bot 拉黑 <QQ号或@成员>`（加入 AI 黑名单，所有群通用）
  - `/bot 解黑 <QQ号或@成员>`（移出 AI 黑名单，恢复 AI 互动）
  - `/bot 黑名单`（查看 AI 黑名单）
  - `/bot mode allowlist|blocklist`
  - `/bot status`
  - `/bot admin add <user_id>`（删除管理员仅允许在 Web 管理页操作）
  - `/bot prefix add|remove|list [prefix]`
- 使用 FastAPI 驱动时，会在 `/qqbot` 挂载本地 Web 管理页和 JSON API；前端文件在 `static/`。
- 可选 Lua 脚本入口，支持通过 OneBot API 获取群列表、群成员、登录信息等。
- 怪物猎人荒野资料查询：`/荒野 技能 <名称>` 返回全部等级效果图，
  `/荒野 任务 <名称或编号>` 返回目标、单人血量、肉质、部位与伤口、炸膛和异常状态图。
- 包含针对策略、存储和 OneBot 事件转换的单元测试。

## 怪物猎人荒野图片查询

在已启用的群中使用：

```text
/荒野 技能 弱点特效
/荒野 任务 走出孤独，名为自由
/荒野 任务 5851
```

技能显示全部等级；任务默认单人，并按怪物、历战类型、奖励级别和任务倍率换算。
连击、蓄力大师、因祸得福、会心击【属性】/【特殊】、属性吸收、属性变换和蓄击强化
会读取计算器补充参数，按武器分组显示具体倍率或增量。连击分初段、后段，
属性吸收区分首击与后续受击；系列技能按装备件数显示。计算器内部 JSON 不进入图片。
缺少的具体参数保留说明，不用零代替，例如蓄力大师的长枪倍率、属性变换的追加伤害值。
血量同时显示基准值与浮动范围。历战王的特殊肉质覆盖对应普通部位，
保留伤痕、伤口、特殊状态及说明；多怪任务逐只列出血量，相同参数的详情共用一组表。
长表自动分页，使用 Python/Pillow 生成 PNG 并作为图片发送，不调用 AI。
同名任务返回含星级、个体强度和编号的候选列表，可用编号重新查询。

功能中心提供“荒野资料总开关”“技能查询”和“任务查询”，默认开启，
沿用现有群白名单/黑名单及限流策略。源资料版本与日期显示在每张图底部。

必要种子数据在 `tools/mhwa/seed.json`，首次查询自动构建与主数据库同目录的
`mhwa.sqlite3`，预先保存 672 条任务怪物的单人血量。图片缓存位于同目录的
`mhwa_cache/cards/`；数据库和图片均为运行产物，不进入 Git。
资料更新后，从中文 Excel 重新生成种子，提交并部署，再重启 Bot；首次查询在事务中
重建资料表，导入失败会回滚，旧资料不被部分覆盖。

```powershell
uv run python scripts/build_mhwa_seed.py "<MHWA数据库_中文.xlsx的路径>"
uv run pytest tests/test_mhwa.py -q
```

导出脚本使用 Python 标准库读取表格，无需额外安装 Excel 运行依赖。
当前种子包含 35 个怪物、601 个任务及 155 个技能，查询不依赖原 Excel 或外部网络。

## 安装

项目固定使用 uv 管理的 Python 3.13.15。先安装
[uv](https://docs.astral.sh/uv/getting-started/installation/)，然后同步项目环境：

```powershell
uv sync
Copy-Item .env.example .env
```

编辑 `.env`：

- 将 `ONEBOT_ACCESS_TOKEN` 设置为和 LLOneBot/NapCat 中一致的 token。
- 将 `QQBOT_ADMINS` 设置为你的 QQ 号。
- 除非你明确想使用黑名单模式，否则保持 `QQBOT_POLICY_MODE=allowlist`。

启动：

```powershell
uv run python bot.py
```

生产服务器使用锁文件同步运行依赖，不安装开发依赖：

```bash
curl -LsSf https://astral.sh/uv/install.sh | env UV_INSTALL_DIR=/usr/local/bin sh
uv sync --frozen --no-dev
systemctl restart qqbot.service
```

`qqbot.service` 继续直接执行 `/opt/qqbot/.venv/bin/python /opt/qqbot/bot.py`，
因此 uv 只负责创建和同步环境，不参与 Bot 运行时进程管理。

也可以构建一个无终端窗口的启动器 exe：

```powershell
.\tools\build_launcher.ps1
```

构建后双击 `dist\QQBotLauncher.exe` 即可后台启动 Bot。启动器会使用本项目的
`.venv\Scripts\python.exe` 运行 `bot.py`，日志按天写入
`logs\qqbot-YYYY-MM-DD.log`。启动器会在后台驻留，跨天时重启 Bot 切换到新日志，
并清理过期日志；默认保留最近 2 天。若只想保留当天日志，可在启动前设置：

```powershell
$env:QQBOT_LOG_RETENTION_DAYS = "1"
```

如果 `127.0.0.1:8080` 已经被其他进程占用，启动器会提示原因，避免重复启动。

## OneBot 连接

推荐使用反向 WebSocket：

```text
ws://127.0.0.1:8080/onebot/v11/ws
```

在 LLOneBot/NapCat 中配置这个地址，并使用和 `.env` 中一致的 access token。
当前项目保持 OneBot 11；OneBot 12 需要协议端明确支持，LLBot/LLOneBot 当前推荐继续使用 OneBot 11 或其文档中明确支持的协议。

如果希望同一个 QQ 账号在桌面客户端里手动发送 `~指令` 也能触发 Bot，需要在 LLOneBot/LLBot 中开启 `reportSelfMessage`。开启后，本项目只处理本人账号发出的前缀指令，例如 `~今日人品`、`~今日菜单`；本人普通聊天、@ 自己、`吃什么`/`csm` 这类免前缀触发都会保持静默，避免影响正常聊天或形成循环回复。

也支持正向 WebSocket，配置如下：

```env
DRIVER=~fastapi+~websockets
ONEBOT_WS_URLS=["ws://127.0.0.1:3001"]
```

## Web 管理页

打开：

```text
http://127.0.0.1:8080/qqbot/
```

如果设置了 `QQBOT_WEB_TOKEN`，访问管理页会先进入登录页；登录后会写入
HttpOnly 会话 Cookie。脚本或调试请求仍可通过 `?token=...` 或 API 请求头
`X-Admin-Token` 传入同一个 token。

如需在小黑盒触发验证码时私聊管理员完成验证，请把 `QQBOT_PUBLIC_BASE_URL` 配置为
外部可访问的 `/qqbot` 地址（例如 `https://bot.example.com/qqbot`）。验证链接为一次性链接，
有效期 10 分钟；验证成功后机器人会自动把解析出的图片发回原群。

Web 管理页可以直接用表单维护触发前缀、前缀触发回复、免前缀关键词回复。

“功能中心”提供 Python 模块和每个 Lua 指令的即时开关；关闭后下一次触发会静默跳过，
不需要重启机器人。管理网站、群策略和 `/bot` 管理命令始终保留，避免失去控制入口。

“Steam 监控”页面用于添加监控群和 Steam 玩家、维护可选 QQ 绑定、查看游玩会话以及
配置状态/成就通知。监控订阅与 QQ 绑定相互独立：未绑定 QQ 的 Steam 玩家同样会被轮询并通知。
先在 `.env` 配置 `QQBOT_STEAM_API_KEY`，再从功能中心开启 Steam 总开关；SGDB 和 ITAD Key
均为可选配置。群内也可使用 `/steam help` 查看 Steam 指令。
保存时会校验规则字段和正则表达式；保存成功后下一条消息会使用新规则。

群内发送 `~海龟汤 [出题要求]` 可开启一局 AI 主持的海龟汤（需开启本群 AI、@回复与功能中心的海龟汤）。
例如 `~海龟汤 惊悚奇幻一点`、`~海龟汤 校园背景，简单一点`；不填要求时自由出题，要求最多 2000 字。
开局先生成并持久化固定汤面、隐藏汤底及关键事实；重复发送 `~海龟汤` 只重看当前汤面，不重开。
已有对局时附加出题要求也不会改题；需先 `@Bot 完成` 或 `@Bot 取消`，再带新要求开局。
本局仅将 `@Bot` 的文字提问和主持回答作为游戏上下文，按群独立存档，多人提问依次处理；
其他 AI 指令在本局期间暂停，随机 AI 插话关闭，普通非 AI 功能保持原有行为。
`@Bot 重试` 会处理尚未回答的问题；回答已生成但 QQ 发送失败时直接补发保存的答案。
`@Bot 完成` 揭晓汤底并结束，`@Bot 取消` 直接退出；两种退出都在本地识别，不依赖 AI 服务。
开局后等待玩家三分钟，收到有效提问时暂停计时，处理、发送完成或失败后重新给出完整三分钟；
无人再 @ 时自动提示结束并恢复普通 AI 对话。失败提示不会写入游戏事实，普通闲聊不会刷新游戏计时。
游戏独立于普通聊天历史，结束时恢复原有对话并排除游戏占用的闲置时间；服务重启可恢复已出题的
存档，若重启前正在处理问题则恢复三分钟等待窗口，正常等待中的局沿用原截止时间。
知识图谱采集和后台提取照常运行，沿用已有的 Bot 指令过滤规则；游戏期间的普通讨论标注为虚构
剧情，提取时不得当作群友本人的真实经历。游戏数据库属于运行数据，不进入 Git 同步。

AI 页面支持创建、编辑、删除多个角色知识库，并随时切换当前启用项；升级时已有的
单一知识提示词会自动迁移为“默认知识库”。切换角色时可同步清空短期聊天上下文。
模型在 AI 页顶部的“AI 链路与供应商”面板选择，消息链路、后台链路可独立选择供应商及模型，知识库不再单独选择模型。
每个知识库可独立设置 Thinking 模式、回复模式、单轮 1 至 3 条连续消息、
最多 50 轮 AI 对话、最多 100 条群聊上下文和 Temperature，也可开启按需联网检索。
开启知识库的“联网搜索与时事评价”后，纯文字请求走同一套语义决策与证据核验流程，不按领域关键词单独分支。
引用图片的请求直接交给当前模型识别，不进入网页搜索、联网决策或证据核验；图片附带文字也遵循此规则。
模型结合最近的用户提问理解当前问题和追问，闲聊、题内推理等直接回答，需要核实对话外事实或明确要求搜索时先检索。
当前请求独立传递，历史提问和群聊只作为背景；只有明确承接旧话题时才继承主题。检索和证据核验始终保留用户原始请求，防止话题切换后重新回答上一题。
冷门名称和简称优先保留原词检索，完整名称匹配的结果优先，再从资料中查找全称和所属领域；不凭字面预设类别。
当前状态按北京时间校验资料的有效区间，不把旧助手结论、训练记忆、最近的索引时间当作当前事实。
默认使用无需额外 Key 的 360、搜狗网页搜索，Bing RSS 备用；模型根据证据缺口选择要读的公开网页，还可继续读取页面中的详情链接，核对相关性、时间与结论依据。
每轮先执行最多两种查询，资料不足时由证据核验结果提出一次补查；最多读取四个有效网页正文，不采用搜索页的 AI 汇总卡片。
候选先按查询相关性排序再截取；当前引擎只返回偏题资料时继续尝试备用源。核验未提出下一步时，会在预算内补读现有候选正文。
联网日志以同一 trace 串联搜索、正文读取、核验与结束原因，区分验证码、网络错误、资料不足和引用不匹配，不记录完整提问或模型回复。
模型返回格式异常与资料不足使用不同提示，避免把核验协议失败误报成没有搜到资料。
正文读取只允许公开 HTTP(S) 地址及受检查的重定向，不访问本地或私有网络，每页最多读取 1.5 MB、保留一万字正文。
最终事实回复必须提供可在本轮来源中逐字定位的原文证据，程序校验来源编号与引用；当前状态还须通过时间有效性核验。
资料不足、过期、无关或输出协议不完整时直接说明无法确认，不把查询失败说成对象不存在，也不退回训练知识编造答案。
检索资料在后台供模型核实，群聊只显示回答和观点，隐藏引用编号、搜索资料和来源列表。
搜索引擎索引时间不等于新闻发布时间，不把刚被重新收录的老页面当作刚发生的新闻。
检索摘要不等于网页全文；回答区分事实、未核实信息和观点，没有检索到资料时直接说明，避免拿旧闻当新闻。
例如：`@Bot 点评今天的科技新闻`、`@Bot 如何看待最近的人工智能监管动态`；也支持引用新闻文字后提问。
群聊 AI 回复请求不指定最大输出 Token，使用模型服务商的默认上限。若服务商仍因长度限制提前停止，Bot 不会发送未完成的回复；DeepSeek 接口开启 Thinking 时会关闭 Thinking 重试一次。
普通和详细模式保留完整回复；模型输出的消息分段超过设置条数时，将多余段落合并到最后一条，不直接丢弃尾文。
简短模式仍按所选短回复规则收束内容。日志记录接口停止原因、输出字数、Token 用量和格式整理前后的长度，不记录回答正文。

“AI 链路与供应商”支持添加、编辑、删除接口，保存名称、地址、密钥、默认模型和超时，
获取并持久化供应商返回的完整模型列表、搜索模型及测试连接。
顶部两组选择分别保存“消息链路”和“后台链路”，切换不需要重启。
@对话、图片识别、随机插话、人物评价、群聊总结和海龟汤使用消息链路；联网规划、检索核验和最终回复整条流程也使用消息链路。
知识图谱提取和关系记忆整理使用后台链路，模型独立保存，切换消息供应商或模型不会改变后台选择。
升级后尚未设置后台链路时暂沿用消息链路，独立保存一次后生效；两条链路共用显式代理开关，已开始的请求保留原有配置。
知识库切换只改变角色设定和对话参数。通用兼容接口使用 `/v1/chat/completions`，
不发送 DeepSeek 专属 Thinking 参数，Gemini 的 `high` 等档位通过模型名称选择。
供应商配置保存在运行机 SQLite 中，密钥不会返回网页、写入审计日志或进入 Git；编辑时密钥留空保留原值。
供应商被任一链路使用时，须先切换相应链路后才能删除。升级时原有接口会保留为备用配置。
供应商可独立选择自动 TLS 或 TLS 1.2 兼容模式；两种模式都校验 HTTPS 证书。
网页启用的供应商复用 HTTPS 长连接，每组供应商地址、TLS 模式、代理及 IP 映射的连接池最多 32 条连接，
保留最多 16 条空闲连接，空闲保留时间为 600 秒；对端提前关闭的连接会重新建立。
延长保留时间可减少重复握手，不会加快上游模型生成或消除线路故障。
连接/TLS 单阶段最多等待 6 秒，连接失败或瞬时网关错误
最多重试一次，并沿用原请求剩余等待时间；生成内容读取超时不会再排队重复生成。
日志分别记录连接、TLS、接口返回和响应读取的耗时，便于区分线路问题与模型生成慢。
接口超时会明确提示“接口请求超时”，不会再混用“脑袋卡住”的通用提示。识图开启 Thinking 时可能需要较长生成时间，可在网页调整供应商的请求超时。
模型明确返回内容拦截标记时，@ 回复会提示“这条消息触发了模型的内容限制，无法回答”，
不会当作网络故障或通过关闭 Thinking 重试。HTTP 成功但正文为空时，在原有超时预算内最多自动重试一次，
保留原模型、问题、图片和 JSON 输出约束；重试仍为空或缺少回答字段时才提示接口没有返回可用回答。
JSON 输出为空或全是空白字符时，这一次重试移除原生 `response_format` 参数并补充格式提醒，
仍校验原有 JSON 业务协议和检索证据。兼容重试返回可解析的 JSON 对象后，按供应商与模型保留十分钟提示词 JSON 模式。
无效工具调用不进入空响应重试；模型的思考文本不会当作最终回答发送。

## 自定义回复

回复规则保存在项目根目录的 `replies.json`。推荐在 Web 管理页用表单修改，
也可以直接编辑文件。保存后下一条消息通常就会按新规则回复，不需要改 Python 代码。

示例：

```json
{
  "empty": "Bot 已启用，请在触发词后输入内容。",
  "fallback": "收到：{message}",
  "rules": [
    {
      "type": "exact",
      "pattern": "菜单",
      "reply": "可用命令：菜单、帮助、状态"
    },
    {
      "type": "contains",
      "pattern": "你好",
      "reply": "你好，我是群助手。"
    },
    {
      "type": "prefix",
      "pattern": "复读 ",
      "reply": "{message}"
    },
    {
      "type": "regex",
      "pattern": "^状态$",
      "reply": "Bot 在线。"
    }
  ],
  "direct_rules": []
}
```

`rules` 用于带触发前缀的消息，例如 `~菜单` 会先去掉 `~` 再匹配 `菜单`。
`direct_rules` 用于免前缀关键词回复，例如群里直接出现某个词就回复。
免前缀关键词应答默认按 10% 概率触发，避免群聊太吵；可在 Web 管理页“策略”里调整，或设置
`QQBOT_DIRECT_TRIGGER_PERCENT=10`。这个概率只影响 `direct_rules`，
不影响 `direct_lua_rules`、`~`、`#bot` 等前缀指令，也不影响 @ 触发。

规则从上到下匹配，命中第一条就回复。`type` 支持：

- `exact`：消息完全等于 `pattern`
- `contains`：消息包含 `pattern`
- `prefix`：消息以 `pattern` 开头，`{message}` 会自动去掉这个前缀
- `regex`：按正则表达式匹配

可用变量：

- `{message}`：处理后的消息；`prefix` 规则会去掉前缀
- `{raw_message}`：原始触发内容
- `{pattern}`：当前命中的规则 pattern

## Lua 脚本

Lua 支持多指令脚本，默认目录为：

```text
scripts/lua
```

群里发送 `~指令 参数` 时，会自动执行 `scripts/lua/指令.lua`。例如：

```text
~抽群老婆
```

会执行：

```text
scripts/lua/抽群老婆.lua
```

当前内置脚本示例：

- `~抽群老婆`：每天为当前用户抽取一个固定群成员。
- `~换个老婆`：当天重新抽取一次群老婆。
- `~强娶 @群成员`：指定一个群成员作为今天的群老婆；抽、换、强娶都会避开当天已经成为别人群老婆的人。
- `~今日天气 北京`：通过国内天气接口查询指定地点的中文天气。
- `~查老师 <姓名> [课程]`：通过 cancir.xyz 的 HTTPS 接口查询教师总体评分和最新4条评论。课程可省略，仅用于筛选老师；搜索结果有精确姓名时只返回该老师，没有精确姓名时匹配1—5位逐条发送画像，超过5位提示补全姓名或添加课程。例如 `~查老师 龙文杰` 查询该老师，`~查老师 龙 模拟电子技术` 按姓名与课程筛选。连续查询复用 HTTPS 连接，网络超时或临时网关错误最多重试一次，整轮查询仍限制在25秒内。
- 转发 QQ 小程序到已启用群聊：小红书与小黑盒图片帖会发送全部图片集合；B站小程序、`b23.tv` 短链与 `bilibili.com/video/...` 视频直链会把封面、标题、作者名和头像合成为粉色主题卡片；不回复 URL，图片只在发送期间临时缓存。B站解析群黑名单可在 Web“群与策略”页面维护，命中群会静默跳过且不影响其他平台。
- 在已启用群聊发送 `x.com/<用户>/status/<ID>` 或 `twitter.com/<用户>/status/<ID>`：自动解析并按推文顺序发送全部图片，无需 @ 或指令；支持带分享参数和 `/photo/1` 的链接。网页“功能中心 → 卡片解析 → 推特图片解析”可关闭此功能。只处理图片，不把视频封面、头像或引用推文的图片混入图集；下载失败时明确提示，不静默发送残缺图集。图片只在发送期间临时缓存。
  推特元数据与原图下载始终使用 `QQBOT_TWITTER_PROXY_URL` 显式代理；留空时沿用环境中的 `QQBOT_AI_PROXY_URL` 地址，独立于 AI 页的代理开关，没有直连回退。通过 FxTwitter 公开接口解析，无需配置 X Cookie。实现参考 [AstrBot Twitter 插件](https://github.com/Ars1027/astrbot_plugin_twitter) 的数据源和代理预下载思路。
- `~今日人品`：每天固定生成 0-100 的人品值和一句短评。
- `~今日宜忌`：按当天农历生成统一的“宜/忌/签语”。
- `~今日菜单`：优先使用国内的 极速数据/JisuAPI 菜谱大全接口随机推荐菜单，返回 `pic` 图片时会缓存并附图；未配置 key 或接口失败时回退到本地中文菜谱库。

  JisuAPI 需要在 `.env` 设置 `QQBOT_JISU_RECIPE_APPKEY`，并保持 `QQBOT_MENU_PROVIDER=auto` 或 `jisu`。本地数据保存在 SQLite，命中有效本地图片时会附图；启动时会自动清理旧的 `今日菜单:cache:v1/v2` Lua 缓存命名空间。
  默认 seed 在 `data/recipes_seed.jsonl`，如需批量导入本地菜谱可执行 `python tools/import_menu_recipes.py --purge-legacy-cache`；`--seed-only` 可只导入本地 seed。

- `~加速 [倍数]`：引用一个动态 GIF 后发送，按指定倍数缩短总播放时长并回发；默认 2 倍，支持 1—10 倍，也兼容 `~加速2`。遇到 QQ 无法正确播放的超短帧时会自动抽帧，处理过程只使用临时文件。
- `~群排行` 或 `~群排行 摸鱼王`：每天按主题随机生成群成员 TOP3。
- `~总结` / `~总结 昨天`：分别整理今天或昨天的真实群消息为 UTF-8 聊天记录文件，交给 DeepSeek 提取话题、群友画像、群聊金句与氛围，再渲染为对应日期的群聊速报长图回发。首次运行会尽力从 OneBot 本地缓存回填目标日期的记录；媒体只记录类型占位符，正文保留 7 天，生成文件和图片位于私有运行数据目录。
  分段笔记、最终报告和 JSON 修复均使用 DeepSeek 最大输出预算 393,216 token；总结单次 DS 请求等待至少 300 秒，若全局 DS 超时配置更长则沿用更长值。
- `/d`：管理员引用普通图片消息或合并转发聊天记录后使用。Bot 会先提示正在工作，再递归下载记录中的图片，以 SHA-256 内容哈希跨日期查重，并保存到私有 MinIO bucket 的 `YYYYMMDD/` 前缀中。
- `/dimg`：仅管理员可用。引用普通图片、QQ 表情或包含图片的合并转发后使用；Bot 会保留 JPG、PNG、GIF、WebP 原文件并按内容查重，保存到 AI 随机表情包库，下一次 AI 随机发送表情时即可选中。单张最大 10 MB，非管理员调用时静默忽略。
- `/dov`：查看 MinIO 图库的图片总数、总大小和今日新增数量。
- `/rm <SHA-256>`：仅管理员可用。按 64 位完整 SHA-256 哈希精确查找并删除 MinIO 图片及图库索引；未找到时不会删除任何图片。
- Web 下载图库可选择本地图片上传查询。服务端计算 SHA-256，仅当图库索引与 MinIO 对象均存在完全相同的图片时显示匹配结果和哈希值。
- `~涩图 [数量]`：从共享的 `/d` 图库随机选取图片。不填数量时随机选 1—5 张并逐张发送；指定数量时可选 1—40 张，合并成一份聊天记录发送。遵循群启用策略和限流。全局 LRU 优先选择从未使用或最久未使用的图片，同批不重复；图库不足时发送实际数量。顺序持久化在 SQLite，读取或发送失败时释放未确认送达图片的预留位置；图片从 MinIO 流式读取至临时目录，发送后清理。

Web 管理页按标签页整理为策略、回复规则、Lua、菜单、饭店。策略页可直接修改核心配置 JSON 对应字段，包括模式、启用/屏蔽群、B站卡片解析黑名单、管理员、@ 触发、前缀、免前缀概率、群限流秒数和用户每分钟限流；菜单页可新增/编辑/删除带图菜单并清理无图 HowToCook；饭店页可新增/编辑/删除饭店和招牌菜。

默认启用，相关配置：

```env
QQBOT_LUA_ENABLED=true
QQBOT_LUA_DIR=scripts/lua
QQBOT_LUA_SCRIPT=scripts/main.lua
QQBOT_LUA_TIMEOUT_SECONDS=10
```

推荐脚本定义 `on_command(event, api)`；兼容旧的 `on_message(event, api)`。
返回字符串时会直接作为 bot 回复；返回 `nil` 时继续走 Web 管理页里的 JSON 回复规则。

`event` 中常用字段：

- `event.command`：指令名，例如 `抽群老婆`
- `event.args`：指令后的参数，例如 `北京`
- `event.message`：同 `event.args`
- `event.full_message`：去掉触发前缀后的完整内容，例如 `天气 北京`
- `event.segments`：OneBot 消息段，例如 `at`、`image` 等，可用于读取被 @ 的群成员。

示例：

```lua
function on_command(event, api)
  if event.group_id == nil then
    return "这个功能只能在群聊里使用。"
  end

  local members = api.get_group_member_list(event.group_id)
  return "当前群成员数：" .. tostring(#members)
end
```

常用 `api`：

- `api.get_group_list()`
- `api.get_group_info(group_id)`
- `api.get_group_member_list(group_id)`
- `api.get_group_member_info(group_id, user_id)`
- `api.get_login_info()`
- `api.get_stranger_info(user_id)`
- `api.send_group_message(group_id, message)`
- `api.send_private_message(user_id, message)`
- `api.reply(message)`
- `api.get_state(key, namespace)`：读取 Lua 持久化状态；`namespace` 可省略，默认当前指令名
- `api.set_state(key, value, namespace)`：保存 Lua 持久化状态
- `api.delete_state(key, namespace)`：删除 Lua 持久化状态
- `api.url_encode(value)`：URL 编码文本
- `api.http_get_json(url)`：请求 HTTP/HTTPS JSON 接口，返回 Lua table
- `api.today_lunar()`：返回当天农历信息，包含年月日、中文月日和稳定 key
- `api.json_encode(value)`：把 Lua table 编码为 JSON 字符串，便于保存到状态
- `api.json_decode(value)`：把 JSON 字符串解码为 Lua table
- `api.call(action, params)`：调用其他 OneBot API
- `api.set_pending_command(command)` / `api.clear_pending_command()`：让同一用户下一条群消息继续交给指定 Lua 指令处理
- `api.save_classic_image(group_id, image_source, image_id)`：保存典图到当前群所属典藏的 MinIO bucket，并返回保存、重复或失败状态
- `api.pick_classic_image(group_id, seed)`：从当前群所属典藏索引里选一张图片
- `api.classic_image(relpath)`：从 MinIO 读取典图并转成可发送的 CQ 图片
- `api.mirror_referenced_image(direction)`：读取当前消息引用的图片并生成对称图；`direction` 支持 `top`、`bottom`、`left`、`right`，处理过程只使用临时文件
- `api.speed_up_referenced_gif(factor)`：读取当前消息引用的 GIF 并按 1—10 倍调整播放速度，返回包含 `status` 和 `image` 的结果

## 测试

### LLBot 合并转发发送超时补丁

服务器 LLBot 7.12.15 默认给合并转发卡片的最终发送回执等待约 10 秒。
本项目提供受版本和源码片段校验保护的补丁，只对 `com.tencent.multimsg` 卡片设置至少 60 秒；
普通文本、图片及其他卡片仍沿用原公式，不缩短大型附件的等待时间。

```bash
cd /opt/qqbot
.venv/bin/python tools/patch_llbot_forward_timeout.py
.venv/bin/python tools/patch_llbot_forward_timeout.py --apply
systemctl restart llbot.service
```

默认只检查，`--apply` 才写入：先用 LLBot 自带 Node 校验语法，备份原文件，再原子替换；重复执行不叠加补丁。
备份位于 LLBot 原目录下的 `llbot.js.before-forward-timeout-<原文件哈希>.bak`。
回滚时用本次输出的确切备份文件覆盖 `llbot.js` 后重启 LLBot。
升级 LLBot 可能覆盖补丁；新版本会拒绝套用，须重新检查源码和测试。
此补丁仅延长等待，不会重试发送，也不保证 QQ 接受消息。

原生合并转发还需启用返回状态修正，避免 LLBot 将 `sendStatus=1`（处理中）或 `3`（失败）当成成功返回：

```bash
.venv/bin/python tools/patch_llbot_forward_timeout.py --native-result --apply
systemctl restart llbot.service
```

此模式等待原生转发进入成功或失败状态，只有 `sendStatus=2` 才返回成功；不自动补发。
